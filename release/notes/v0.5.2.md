# JSON API Forge v0.5.2

Runtime correctness, bounded network waits and server release delivery.

- Harden Editor project/document containment using canonical paths and separator-terminated roots; reject ambiguous original spellings, linked control paths, and Windows device/alternate-stream names. Project staging preserves directory-derived defaults.
- Provision `.env` and secret exports atomically; refuse linked destinations and accidental redirected secret output. Existing generated API-key digests remain compatible; Editor passwords continue to use salted scrypt.
- Run CodeQL regression tests in the platform-build preflight; normalize coverage report paths and generate schemas/manifests with LF on Windows and POSIX.

- Isolate SQL/Mongo read caches by resource visibility and owner-bypass policy while keeping shared table/collection invalidation.
- Preserve heterogeneous batch fields and defaults in one transaction; fix ISO datetime coercion, nullable cursor continuation, PUT scalar/server defaults and PostgreSQL BIGINT declarations.
- Reject non-finite numeric parameters and malformed boolean filters; malformed signed-media signatures return false.
- Clean saved media after deduplication, quota/metadata failures and cancellation.
- Apply one connection deadline to DNS and every candidate address. Fix double decoding of gzip responses and remove redundant data-source DNS lookup while retaining transport SSRF/rebinding checks.
- Reuse app-scoped JWKS clients, bound complete JWKS calls including lock waits, and rate-limit unknown-key refresh attempts and provider outage retries without serving expired keys. New `security.jwks_refresh_interval_seconds` defaults to 5; newly rotated unknown keys can wait up to this interval.
- Cancel the actual ASGI endpoint task on pre-response request timeout, preserving streaming behavior and waiting for cooperative cleanup. Running synchronous hooks/SQLite work may outlive the deadline.
- Isolate blocking DNS in a lazy process-scoped executor; static/file-only sources no longer construct HTTP clients.
- Add optional HTTP-source `total_timeout_seconds` (default null) to budget retries and streamed reads without changing legacy phase timeouts.
- Restrict auto-create schema checks to the current table, preserving existing data, and measure schema/reflection startup stages.
- Run readiness probes concurrently with process-wide limits (`READINESS_TIMEOUT_SECONDS=3`, `READINESS_MAX_CONCURRENCY=8`); preserve response structure and degraded status semantics.
- Reuse reflected tables and expose fixed-label authentication, queue-wait and SQL/Mongo startup histograms through the existing protected metrics endpoint.
- Add manual validate/draft/publish workflow with exact-SHA CI/CodeQL/platform gates, artifact provenance, complete per-file checksums, archive integrity checks, resumable draft uploads and remote digest/tag verification.

Existing project configuration remains accepted. No automatic database migration or Passenger bridge replacement occurs. Existing BIGINT columns need an explicit, reviewed migration to change physical types. Nullable secondary cursors now sort nulls first consistently; start a new pagination session after upgrading. PUT resets omitted nonnullable fields with scalar/server defaults; callable defaults require an explicit value.

YoungLion's hosting worker startup/idle eviction can still produce a slow first request. Compare warm request percentiles with a request immediately after an idle window; application timeouts and connection reuse cannot remove process startup time.

Release scope is the server distribution on `main`. Editor and Python SDK assets remain owned by their independent branches. The publisher refuses any existing public tag release and any draft with extra component assets; aggregate publishing requires a separate per-component manifest.

Controlled latency results and reproducible probes: `docs/performance/v0.5.2-latency-analysis.md`. These are local measurements against the initial v0.5.2 development commit, not evidence that YoungLion hosting latency is resolved.
