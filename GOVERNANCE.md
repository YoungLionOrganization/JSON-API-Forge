# Governance

JSON API Forge currently uses a **central project-owner governance model**.

Cavanşir Qurbanzadə (@Cavanshirpro), as the current Project Owner, controls the canonical repository and has final authority over roadmap, architecture, merge decisions, release designation, compatibility policy, branding and project licensing. Contributors can propose, review and implement changes, but contribution alone does not create release authority or ownership of the project as a whole.

## Official releases
Only the Project Owner or explicitly delegated maintainers may designate an Official Release. A commit, fork, branch, patch set or build made by another person is not an Official Release merely because it is publicly visible.

## Contributions
External contributions are welcome when the repository is accepting them. Contributions must satisfy `CONTRIBUTING.md`, the project license and `CONTRIBUTOR_LICENSE_AGREEMENT.md`.

## Licensing changes
The Project Owner may change the license for future releases, offer separate commercial terms, or adopt dual/multi-licensing. Contributor licensing is structured to make that possible without losing central control of future release policy.

## Security
Security-sensitive changes may be reviewed or developed privately until coordinated disclosure is appropriate.
