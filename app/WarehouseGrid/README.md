Inventory batch ownership, allocation workflow, audit events, quantity totals and bounded search/filter surfaces.

## What this example demonstrates

| Area | Included behavior |
|---|---|
| Main records | `warehouse/inventory_batches` CRUD with bounded inputs, soft deletion and ownership policy |
| Atomic imports | Up to 100 primary records per transaction, with per-row defaults |
| Supporting records | Policy, assignment and audit resources |
| Workflow | Three transactional/analytics RPCs; states: `received`, `stored`, `allocated`, `picked`, `depleted` |
| Access | Scoped `operator` and read-only `auditor` roles, plus administration |
| Runtime | In-memory cache/rate limits and a bounded `warehouse-grid-updates` event channel |
| Editor | An operation graph in `graphs/domain-transition.forgegraph.json` |

## Install and run

Install the [main runtime](https://github.com/YoungLionOrganization/JSON-API-Forge/blob/main/INSTALL.md) at v0.5.2. From the exampleApps checkout, copy this project into that server:

```bash
bash scripts/install-example.sh WarehouseGrid /path/to/JSON-API-Forge-main/app
```

PowerShell users can run `scripts/install-example.ps1 -Name WarehouseGrid -Destination C:\path\to\JSON-API-Forge-main\app`. Then run these commands **from the main server root**, with its Python environment activated:

```bash
forge init
forge validate
forge doctor
forge dev
```

Open `http://127.0.0.1:8000/api/warehouse-grid/v1/_docs`. Use the bootstrap variable declared in `config/20-security.json` to provision appropriately scoped credentials; do not publish the generated `.env` or use an administrator key in a browser. Transactional operations that require idempotency must receive an `Idempotency-Key` unique to the logical command.

## Explore and adapt

Use `POST /api/warehouse-grid/v1/warehouse/inventory_batches/_batch` for up to 100 records in one transaction. The request body is an array of create payloads; the whole batch rolls back on a validation or constraint failure. This endpoint does not implement idempotent replay, so reconcile application identifiers before resubmitting after a network failure.

Read `app.json` for the API prefix, `config/40-resources.json` for allowed CRUD fields/actions, `config/50-operations.json` for SQL/RPC contracts, and `config/60-events.json` for channel permissions. Keep changes to JSON configuration validated with the main runtime.

This README and the numbered fragments are generated by `scripts/generate_example_catalog.py` in exampleApps. Change that generator when contributing catalog updates, then run it and its `--check` mode. A private deployment can adapt its own copied configuration under the project license.
