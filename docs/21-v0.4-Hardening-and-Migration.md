# v0.4 Hardening and Migration

v0.4 intentionally made several previously permissive behaviors fail closed: placeholder/default secrets, implicit public endpoint types, unknown config fields, weak proxy trust, broad credential delegation, writable policy fields and unbounded runtime states.

v0.4.1 is a patch within that hardening line. It removes the accidental legacy root project layout, fixes replay metadata/hook semantics, updates response-class compatibility and dependency/security floors, and adds stronger release-tree integrity checks.

When migrating, run `forge validate` first, then `forge doctor`, explicit migration, representative tests and production doctor. Do not “fix” validation by broadening permissions or making protected fields writable; understand the boundary the validator is enforcing.
