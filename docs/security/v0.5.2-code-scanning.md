Path handling follows [CodeQL's normalization guidance](https://codeql.github.com/codeql-query-help/python/py-path-injection/)
and [Windows reserved-name rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file),
and includes the separator in the containment prefix so a sibling such as
`Notes-private` cannot pass the `Notes` boundary. Linked control directories and
documents are rejected before listing, reading, validation and staging. The
fixed staging directory preserves manifest defaults derived from the real
project directory. The deployment account must control the project root;
these checks do not isolate arbitrary concurrent filesystem changes by other
local accounts with write access to that root.

Windows secret files inherit the deployment directory's ACL. POSIX files are
private from creation, including force rotation. Exclusive publication preserves
a destination created concurrently, and force rotation detects changes while
the replacement is being prepared. Tests cover linked targets, concurrent
creation/rotation, cleanup and redirected-output opt-in.

## Remaining alert review

**Original alert #5:** `forge secrets` is an operator command whose purpose is to
export a new credential. It does not run in application request handling and does
not use the runtime logger. Redirected output is refused by default. `--output`
writes the credentials to a file and prints only its path/count; `--stdout` is
an explicit export choice. The residual CodeQL print finding is expected and can
be dismissed as a false positive with this rationale. Do not use `--stdout` in
retained CI logs or shell transcripts.

**Original alert #60:** `hash_key` hashes keys generated by
`secrets.token_urlsafe(36)`, not human-chosen passwords. It is a deterministic
database lookup digest, with 288 bits of input entropy. Keeping it preserves
existing issued keys and avoids expensive password hashing on unauthenticated
lookup requests. Editor passwords separately use salted scrypt. The regression
test authenticates an existing digest record and rejects a modified token.
The residual password-hashing finding can be dismissed as a false positive;
this helper must never be repurposed for password storage.
